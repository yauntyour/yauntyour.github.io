功能特性

功能所在位置
🤖三种 API 风格——OpenAI Chat Completions（{base}/chat/completions）、OpenAI Responses（{base}/v1/responses）和 Anthropic（{base}/v1/messages），均支持流式与非流式，并支持按提供方配置 HTTP(S) 代理cell::llm、cell::net
🧩提供方注册表——任意数量的命名端点；模型列表从提供方实时获取，只持久化当前激活的模型名cell::config
🔧9 个内置工具——ls、read、write、edit、rg、exec、find、tw、noticecell::box、cell::tools
👥Teamwork——受监督的子代理，可配置工作流（tw 工具 + /teamworks）：命名阶段、每阶段调度模式、监督门控、同任务复用、带协作式停止的后台运行、每个子代理可单独指定提供方/模型/思考等级、复用先前子代理（可选择是否重放其对话记录）、可查询历史与报告，以及文件租约——按子代理授予写入权限，并强制审查它对被授权文件所做的每一次修改cell::teamwork
📣通知——代理会话之间的零 token 消息总线：Teamwork 子代理报告进度，监督者在 /notices wait 中空闲并会被立即唤醒，全程无需一次 LLM 往返cell::notice
🛡️三种沙箱模式——read-only、edit-only、full-access；凭据/运行时文件在所有模式下均不可访问，exec 是唯一需要确认提示的工具cell::box::check_exec
🧨提示注入清理器——每个 exec 结果都会扫描命令覆盖指纹，能抵抗同形字、零宽字符、标点连接 token 和多行拆分cell::box::sanitize_output
🔐加密凭据保险库——Argon2id 密钥派生 + AES-256-GCM（XChaCha20-Poly1305 回退），sodium_malloc/sodium_memzero 秘密缓冲区cell::encrypt
💬按目录会话——会话 id 嵌入工作目录的哈希；切换会话会跟随其 cwdcell::chat
⏸️可中断轮次——Esc 或请求失败会保留部分回复（截断到最后一个 token），取消任何半流式工具调用，追加一条说明原因的系统消息，并记住状态，使 /reload 从轮次停止处继续cell::chat::record_interrupt
🗜️自动上下文压缩——在上下文溢出错误时（压缩并重试一次），以及在长时间工具密集型轮次后；压缩模型可以不同于聊天模型cell::chat、compact()
🧠思维链——/think 有 5 个等级（off/low/med/high/max）；OpenAI 流式输出 reasoning_content，Anthropic 流式输出 thinking_delta，两者均以暗色渲染；推理内容会持久化到会话中cell::llm
🔎带行号读取——read 返回的每一行都带右对齐行号，rg 将命中分组为 === file === + line: content，因此模型可以引用准确行号来 editcell::box
📦技能——.cell/skills/ 下带 YAML front matter 的 Markdown 文件（递归、支持目录式），作为系统消息注入cell::skills
📊使用统计——按模型和按会话的请求/token/字符计数器，以及提示缓存命中率cell::stats
⚡异步 I/O——会话/配置/统计写入会被合并，并由一个后台线程刷新；动态工作池并发运行只读工具调用cell::async_io、cell::sys::thread_pool
🖥️跨平台——Windows（Job Objects、cmd.exe、UTF-8 代码页、虚拟终端）和 POSIX（fork/exec、termios）；所有 OS 相关代码隔离在一个命名空间中cell::plat
🧪自测——数百条断言，覆盖沙箱、编辑器、清理器、加密、配置、会话、技能、统计和工具注册表--selftest

快速开始

先决条件

  • 一个支持 C++26 的工具链，且标准库支持 <format>、<expected>、<generator>、<span>、<concepts> 和 std::move_only_function——例如 GCC 15+（MSYS2 UCRT64）或较新的 MSVC/Clang。这非常前沿：请使用较新的标准库，而不是 LTS 版本。
  • libcurl（任意较新的后端）、libsodium、nlohmann/json（仅头文件）。
  • 推荐的包管理器：vcpkg

运行

在 REPL 中，无需重启即可管理提供方：

命令行选项

选项值效果
--provider名称按名称选择已有提供方；如果没有匹配项，则创建一个提供方，其名称同时作为 API 风格（openai / anthropic）；对于没有显式风格的 OpenAI 风格提供方，API 风格默认为 openai-chat。切换到不同提供方会清除 current_model——已存储的模型名属于前一个提供方——而重新选择已经激活的提供方（包括空的 current_provider 情况，表示“第一个提供方处于激活状态”）会保留它；同一命令行中显式的 --model 会在之后应用。
--baseURL在当前提供方上设置 base。没有内置默认 base——空 base 意味着提供方不可用，直到你设置一个。
--model字符串激活的模型名，按原样存储（不必出现在 /models 中；不匹配只会警告）。
--proxyURL当前提供方的 HTTP(S) 代理，凭据可以内嵌。localhost、127.0.0.1、::1 始终绕过它（CURLOPT_NOPROXY）；HTTPS 目标通过 CONNECT 隧道。
--key秘密加密写入 .cell/.crypt，id 为 provider:<name>，并绑定到当前提供方；明文副本立即清零（sodium_memzero）。
--sessionid存储为 cfg.session_id。参见实现说明：启动时总是打开新会话，因此请用 /session ID 恢复。
--system文本完全替换系统提示。
--sandboxread-only/readonly、edit-only/edit、full-access/full设置 exec 沙箱模式并持久化为 sandbox_mode。未知值会警告，并将存储值改写为 full-access。
--no-color标志禁用 ANSI 颜色（反正只有当 stdout 是终端时才会使用颜色）。
--verbose标志将 DEBUG 日志行镜像到控制台（它们始终写入日志文件）。
--selftest标志在隔离的 .cell-selftest/ 目录中运行内置测试套件并退出（0 = 全部通过）。
--help、-h标志打印用法摘要并以 0 退出。

加载顺序。 首先读取 .cell/config.json（解析错误会作为警告报告，程序继续使用默认值）；旧配置形态会在加载时迁移。然后 CLI 标志应用在已加载设置之上。退出时合并后的配置会写回，因此 --base / --model / --proxy / --sandbox 更改是持久的。

API 密钥解析（每次请求，先匹配者胜）：

  1. 绑定到当前提供方的保险库条目（provider:<name>）；
  2. 环境变量 OPENAI_API_KEY / ANTHROPIC_API_KEY（由提供方风格选择）；
  3. 通用保险库条目 api_key。

如果都不可用，该轮次会失败，并给出解释如何设置的提示信息。

数字参数。 配置字段和工具参数同时接受 JSON 数字和带引号的数字字符串（"log_max_lines": "500"、{"offset": "85"}）；垃圾值或缺失值会回退到默认值而不是抛出异常。

思维链（/think）。 对于 OpenAI 风格提供方，不额外发送任何内容——推理模型已经流式输出 delta.reasoning_content，/think 会在答案前以暗色显示它，因此非推理模型不受影响。对于 Anthropic 风格提供方，请求体会增加 thinking: {"type":"enabled","budget_tokens":N}（其中 N 取决于等级：low=1024、med=2048、high=4096、max=8192；max_tokens 会相应提高），流式 thinking_delta / signature_delta 块以暗色渲染；思考块保留在存储的助手消息中，这是 Anthropic 在工具调用跟随思考轮次时所要求的。对于 OpenAI，reasoning_content 现在会存储在会话中，以便跨重启持久化。

技能（/skills、/skill）。 技能是 .cell/skills/ 下的 Markdown 文件，仅当它以 YAML 风格 front matter 块开头时才会被发现；扫描器会递归（深度 ≤ 6），因此目录式技能也可用：

name 回退到文件主干名——对于 SKILL.md/README.md 则回退到父文件夹名——description 回退到第一条非空正文行（截断到约 120 字符）；周围的引号会被剥离。只要存在有效技能，每个新会话都会得到一份仅元数据的“可用技能”列表，作为系统消息注入，以便模型可以建议加载某个技能；/skill NAME 会将完整正文（移除 front matter）作为系统消息追加到会话剩余部分。名称和描述会经过 display_safe（控制/ANSI 剥离），但不会进行指纹脱敏——重量级扫描保留给 exec 输出。

上下文压缩（/compact）。 每条 system 消息都原样保留；其他每条消息都拆分为对话文本和代理推理（思考块会在第二遍中摘要），每条消息截断到 400 字符，两部分都发送给压缩模型（compact_provider / compact_model，回退到会话模型），并禁用工具。两份摘要合并成一条 {"role":"system","content":"# Here is a summary that captures the previous conversation: …"} 消息，并且保留最近一条用户消息——压缩结果至少需要一次真实轮次，因为只有系统消息的对话记录会被许多聊天模板拒绝（No user query found in messages），并且会让溢出重试没有东西可重新发送。待聚合消息 ≤ 12 条时，它会报告“上下文已经很小”并且不做事；如果摘要调用失败，则使用截断占位符。摘要插入前会再次经过注入清理器，并且 read-before-edit 日志会重置，因为较早的 read 结果已从上下文中消失。压缩本身每部分都是一次 LLM 请求，并计入使用量。

对话记录形态。 Chat Completions 服务器用自己的聊天模板渲染对话记录，严格的服务器（llama.cpp 的 Jinja 模板）只接受恰好一条 system 消息，且位于最前面——第二条，或跟随某轮之后的系统消息，会失败并报 System message must be at the beginning。因此，每当会话状态在对话中途到达（通知、已加载技能、中断说明、压缩摘要），所有 system 消息都会按对话记录顺序合并到唯一的前导系统消息中（chat::fold_system_messages），并且每次请求前也会对对话记录运行同样的合并，作为最后一道防线。另外两种 API 风格从不关心这一点：它们本来就会把系统消息从数组中取出放入 system / instructions。

自动压缩。 两个触发条件，都使用同一个 compact() 路径：

  • 上下文溢出时——当请求失败且错误匹配已知 OpenAI Chat Completions / OpenAI Responses / Anthropic 的“上下文长度超限”短语（大小写不敏感匹配，例如 maximum context length、context_length_exceeded、prompt is too long），会话会被压缩一次，同一轮会针对压缩后的上下文重试，且不计为失败尝试（[auto-compact on context overflow]）。
  • 长时间代理运行后——当 compact_auto 开启（默认）且某轮记录了 ≥ 3 次工具调用以及推理/思考条目时，该轮之后会压缩上下文（[auto-compact] …）。用 /compact auto off 禁用。

工具

注册了九个工具——ls、read、write、edit、rg、exec、find、tw 和 notice——并为当前 API 风格生成 schema （OpenAI 为 {"type":"function","function":{…}}，Anthropic 为 {"name":…,"input_schema":…}，Responses API 为 {"type":"function","name":…,"parameters":…}）。

工具策略参数行为

glob 工具已合并进 find：find 接受 pattern glob 和/或 name/newer_than_hours/larger_than_bytes 元数据过滤器。

执行调度。 在一个助手轮次内，所有 Policy::Allow 只读调用（ls/read/rg/find）都会在共享工作池上并发分派；write 和 edit 被有意推迟到第二轮顺序执行，以便同一消息中的读取总是先完成（read-before-edit），并且同一文件的两个编辑永不竞争；exec 在交互确认后顺序运行，tw（Teamwork）也在该顺序轮次中运行，因为它会阻塞在子代理上。结果按原始 tool_call 顺序追加到对话记录。

Read-before-edit 规则。 路径会被规范化（weakly_canonical，Windows 上小写化），读取工具返回的行范围会被记录。edit 拒绝触碰任何未被先前读取范围覆盖的行，并且只要可见上下文变化（/clear、/new、/session、/compact），日志就会清除。

文件缓存。 edit 通过以规范化路径为键、经 (size, mtime) 验证的缓存读取，因此同一文件的连续编辑可以跳过磁盘，而外部写入者总是会被发现。

Teamwork

Teamwork 运行受监督的子代理。主代理创建一个任务，其中包含子任务列表——可选地排列为命名阶段的工作流——串行或并行运行它们，并取回合并报告。每个子代理都有独立的消息历史；子代理被限制在其租约覆盖的文件内，并且永远不能自己调用 tw，因此层级保持为深度 1 的树。子代理可以调用 notice，这是它们在运行中向监督会话报告进度的方式。

任务与会话共存：<root>/sessions/<cwd-key>/<session-id>/teamworks.json，每个子代理有一个 <session-id>/<job-id>/<worker>.json 对话记录。任务 id 是 UTC 墙钟时间戳——tw-YYYYMMDD-HHMMSS（-N 后缀消除同秒冲突）。存储保存在内存中，并通过异步写入器镜像到磁盘，因此列出/查询任务没有磁盘 I/O。

文件租约与监督审查

子代理始终可以创建新文件：文件被创建的那一刻它就属于该子代理，之后该子代理可以自由重写它。其他所有事情按路径决定：

目标文件发生什么
不存在，并用 write 创建允许——它成为子代理自己的文件
是子代理之前创建的文件允许
被租给此任务的另一个子代理拒绝：leased to <child>（所有权也是互斥锁）
存在且无人租用除非在子代理的 editable 列表中，否则拒绝
在子代理的 editable 列表中被审查——见下文，每一次都如此

主代理授权列表上的文件仍归主代理所有：针对它的每次 write/edit 都会被暂缓，同时一次监督审查仅根据 edit_rules 判断这一个更改。审查是向主会话的提供方/模型发出的一个短请求，携带路径、工具参数、文件当前内容以及它将产生的结果——缺失或失败的审查会拒绝（fail-closed），绝不静默允许。

拒绝不是致命的：子代理会收到裁决和原因作为工具结果，并可以修正更改后重试（每个子代理最多 8 次审查）。租约从不比一次运行活得更久——任务完成、停止或删除时会被丢弃，被拒绝的子代理永远不会阻塞其兄弟，因为绘制文件只在审查进行期间声明它。

审查是并发的：没有子代理会排队等待另一个的审查，因为租约锁在发出审查请求之前就已释放。

给定 editable: ["story.md"], edit_rules: "append at most one paragraph, never alter existing lines"，一个追加其章节记录的子代理会通过；一个试图重写文件的子代理会得到 [edit] /work/story.md refused: the supervisor rejected this change: rewrites existing lines，然后通常将其版本写入自己的新文件。

阶段字段：name（默认 stage_N）、mode（默认 serial | parallel）、gate（此阶段后暂停等待监督者）、provider/model/think（阶段默认值）、agents（必需，非空）。裸 reuse 必须命名较早阶段的 worker——这在任务创建时验证。

子代理的模型解析顺序：它自己的字段 → 被复用子代理的字段 → 阶段默认 → 任务默认 → 被复用任务的默认 → 激活的提供方/模型。不存在的 provider 是错误，绝不静默回退。每个子代理构建自己的 LLM 客户端，并在其所有轮次中复用它，因此并行子代理永不共享 curl 句柄。

工作流执行、门控与监督

  • 阶段按顺序运行；一个阶段内的 worker 串行或并行运行（受池限制）。每个阶段之后都会持久化当前进度（next_stage），因此门控暂停、停止或崩溃永远不会丢失已完成阶段的报告。
  • 门控：带 gate: true 的阶段会在下一阶段之前暂停任务（status=waiting）并发送通知。监督者审查阶段报告，并用 tw run、/teamworks run ID / resume ID 恢复，或用 edit 重新规划。
  • 后台运行：/teamworks run_bg ID（或带 background:true 的 tw run）在专用运行线程上执行剩余工作流，同时 REPL 保持交互。监督者可以在 /notices wait 中空闲——零 token——并被每次阶段/worker 转换唤醒。
  • 停止：/teamworks stop ID 请求协作式停止；任务在下一个 worker 轮次或阶段边界暂停（status=waiting，被中断的阶段在恢复时重新运行）。
  • 启动恢复：进程在任务运行时退出会使其保持 running；下一次启动会将此类任务标记为 failed，以便重新运行或移除。

报告

已完成任务会在 summary_reports 中记录每个子代理的 {status, summary, rounds, tool_calls, provider, model, reused, reviews_approved, reviews_denied}——两个计数器告诉你监督者通过和拒绝了被授权文件的多少次修改。当报告缺失时——例如子代理运行中途被中断——tw operation:"report" 会回退到子代理持久化的对话记录，并返回其最后一条助手文本，因此结果仍可恢复。

调度与失败处理

  • serial 任务在调用线程上一个接一个运行子代理；parallel 任务通过共享工作池分派，因此并发受 thread_pool_size 限制（默认 16），而不是每个子代理生成一个线程。工作流阶段按阶段继承相同规则；后台运行在自己的专用运行线程上执行（绝不在池上），因此池托管的运行永远不会死锁，并在退出时 join。
  • 抛出的子代理会被捕获并报告为 failed；任务在重启后永远不会卡在 running（启动恢复将中断的运行标记为 failed）。任务还为每个子代理携带 ok / incomplete / failed / stopped，其中 incomplete 表示子代理达到 8 轮限制而未产生最终答案。
  • 子代理运行以真实 token 数计入使用统计，键为 <job-id>-<child-name>。

通知

notice 系统是代理会话的消息总线。任何写入者——来自 REPL 的用户、此进程内的 Teamwork 子代理，或共享运行时根目录的第二个 cell 进程——都会向目标会话的 notices/pending/ 文件夹投放一个 JSON 文件（原子写入，读取时清理：仅 UTF-8，剥离控制/ANSI 字节，16 KB 正文上限，500 个待处理文件上限）。已送达通知归档到 notices/seen.jsonl。

等待是零 token 的。 /notices wait（以及 notice 工具的 wait 操作）在条件变量上阻塞，并周期性重新扫描文件夹（约 0.7 秒）——空闲时不发出 LLM 请求。进程内发送会立即唤醒等待者；跨进程发送约 1 秒内到达。待处理通知也会在每次 LLM 轮次前自动排空，因此监督者永远不必轮询。

  • 发送：/notices send [SESSION] TEXT，或 notice 工具（from/topic 字段给接收者路由提示）。Teamwork 子代理以此报告进度——notice 是它们在沙箱之外唯一可用的工具，在所有任务模式中都是。
  • 自动进度：每个 Teamwork 任务都会为任务开始/完成/失败、阶段开始/结束、门控暂停、停止，以及每个 worker 开始/结束（带状态和摘要片段）发送通知，全部 from=teamwork/<job-id>[/<worker>]。
  • 消费：/notices drain（或 notice drain）将待处理通知作为上下文送入对话；wait 送达它被唤醒所等待的内容；clear 丢弃它们。由于在排空锁下删除文件，每个排空会话恰好送达一次。

安全模型

六个独立层，从路径一直到屏幕上显示的字节。

1. 沙箱模式

用 /sandbox [mode]、--sandbox MODE 或 sandbox_mode 配置键设置。在任何命令运行之前，工具会按模式被允许或拒绝：

模式允许的工具exec
read-onlyread、rg、find、ls（以及任何只读运行）完全阻止——在确认提示显示之前就被拒绝
edit-onlyread/rg/find/ls 加上 write/edit允许，受第 2–3 层门控约束
full-access（默认）所有工具允许，受第 2–3 层门控约束

任何模式下都不过滤网络出口——命令门控仅针对路径（参见第 3 层和实现说明）。第 2 层的敏感路径规则在所有地方适用。exec 是唯一由人工确认提示门控的工具（第 4 层）；在 read-only 模式下，exec 在提示显示之前就被拒绝。

2. 路径门控——check_path / is_sensitive_path

  • 参数中的任何 .. 都会被拒绝；
  • .cell 运行时目录下的一切都不可访问（保险库、.key、config.json、会话、日志）——除了 .cell/skills/，技能系统合法读取它；
  • 磁盘上任何位置的知名凭据存储都会被阻止：~/.ssh/id_{rsa,ed25519,ecdsa,dsa}、~/.aws/{credentials,config}、~/.netrc、~/.npmrc、~/.pypirc、~/.git-credentials、~/.git/config、~/.git/hooks、~/.config/gh/hosts.yml、~/.docker/config.json、~/.kube/config、~/.m2/settings.xml、~/.gradle/gradle.properties；
  • 路径首先用 weakly_canonical 规范化（解析符号链接/junction），因此指向凭据文件的链接也会按其字面名称被阻止。

对于 write/edit，只检查 path/dirpath 字段——代码内容可以合法包含 >、| 或 ..。

3. 命令门控——check / check_exec

沙箱仅针对路径：命令字符串会检查路径遍历（..）和敏感路径（/.crypt、/.key、/config.json、/sessions/、/logs/，两种分隔符，大小写折叠）。它不尝试通过解析命令名来阻止网络出口、解码编码载荷，或禁止 shell 操作符——威胁模型假设一个不受信任的代理运行在受信任的主机内，其中 exec 命令由用户确认（或在 full-access 中 autoallow）。在 read-only 模式下，exec 直接拒绝。另请注意，exec 仍可运行解释器，例如 python3 -c "exec(base64…)" 或 cmd /c "echo …"，因为门控只检查路径，不检查内联代码。（第 2 层更广泛的凭据存储列表由 check_path 对工具路径参数执行，而不是由 check_exec 执行。）

通过沙箱的高风险命令仍要求第二次确认：递归/强制删除（rm -rf、rm -r -f、del /s、rmdir /s……）、权限更改（chmod、chown、sudo、cacls、icacls、takeown）以及可能触发钩子或重写历史的 git 操作（commit、merge、rebase、cherry-pick、am、apply、checkout、switch、stash、clean、reset、restore）。

4. 人工确认

exec 是唯一的 Ask 工具：allow exec({…})? [y/N]——参数通过 display_safe 打印，因此注入的 JSON 无法擦除提示或伪造批准。当autoallow 模式启用时（/autoallow on，仅 full-access 沙箱），由 LLM 单独决定 exec 命令是否无需用户确认即可运行——沙箱检查（敏感路径）仍然适用。批准拒绝（来自用户或 autoallow）会结束当前代理运行；沙箱安全拒绝作为正常反馈返回给模型。

5. 输出加固

  • sanitize_output（应用于 exec 结果，以及从磁盘重新加载的带 exec 标记的结果）：先截断到字节上限（默认 128 KiB；代理循环传 512 MiB），然后逐行根据约 50 个命令覆盖指纹加三个正则族（动词 + 填充词 + instructions|rules|system prompt|sandbox|safety、you are now …、no longer bound …）进行脱敏。匹配在每行的扁平化形式上运行：UTF-8 解码，全角/拉丁-1/西里尔/希腊同形字折叠为 ASCII，零宽和双向标记删除，标点折叠为空格，并将最多 6 个相邻行的窗口连接，以便拆分指纹仍能匹配。工具输出包装框架行永远不会被脱敏（它们带有重新加载时使用的 tool="exec" 标记）。
  • wrap_tool_output：每个结果都包裹在显式的不受信任数据边界标签中，该标签携带工具名和路径/命令标记，属性会被清理，正文中该闭合标签的任何出现都会被转义，因此注入内容无法伪造嵌套的“已授权”工具块或突破包装器。
  • truncate_output：非 exec 结果获得大小上限（512 MiB），但不进行注入扫描。
  • display_safe（单行，剥离 ANSI）用于确认提示和技能元数据；console_safe（多行，剥离 ANSI）用于工具输出的青色控制台回显，另外上限为 16 KiB。

6. 凭据保险库

.cell/.crypt 是一个 JSON 信封（version: 2），包含随机 base64 盐，以及每个键的 {nonce, ct} 对。AEAD 密钥通过 Argon2id（中等 ops/内存限制）从以下来源派生：

  • 如果设置了 CELL_VAULT_PASSPHRASE 环境变量，则使用它，否则
  • .cell/.key——32 个随机字节，首次使用时自动生成（磁盘上为 base64）。

当 CPU 提供 AES-NI 时，加密使用 AES-256-GCM，并透明回退到 XChaCha20-Poly1305。秘密保存在 secure_string 中（sodium_malloc 缓冲区，销毁时清零，常量时间比较）；派生密钥在保险库析构函数中擦除。明文永远不会出现在保险库文件中——自测会断言这一点。

会话与工作目录模型

  • 每个会话 id 为 <cwd-key>-<unix-millis>-<8 random hex>；cwd key 是规范化绝对工作目录 SHA-256 的前 16 个十六进制字符（Windows 上小写化）。
  • 每个会话是一个文件夹：.cell/sessions/<cwd-key>/<id>/。它包含 JSONL 对话记录 messages.jsonl（每行一个消息对象——标准代理日志形态）、Teamwork 存储 teamworks.json 及每个任务一个 <job-id>/ 对话记录目录、压缩归档 saved/msg-<UTC time>.jsonl，以及中断状态 interrupt.json（轮次被缩短时写入，下一条用户消息或完成 /reload 时清空）。.cell/sessions/sessions.json 是 hash → path 索引，使每个分组都能解析回真实目录；/sessions 按它分组，并用 > 标记当前 cwd。
  • /session ID 和启动恢复逻辑跟随会话的 cwd（通过索引解析，current_path + 缓存失效），因此工具继续操作对话所属的项目；/session 和 /session rm ID 会重置 read-before-edit 日志，因为记录的读取不再适用。切换到已有会话会再次打印其最后五条用户/助手文本消息，省略思考和工具调用内容。
  • /new 保留旧文件夹（可重新访问），/clear 保留 id，/session rm 删除整个文件夹和使用记录；孤立的 usage 记录在启动时和 /usages 时修剪。
  • 压缩归档：每次 /compact（手动或自动）都会先将完整对话记录写入会话文件夹中的 saved/msg-<UTC time>.jsonl（同秒归档获得 -N 后缀），然后才重写上下文；如果归档或摘要无法产生，上下文保持不变。/saved list、/saved show NAME 和 /saved rm NAME 访问当前会话的归档。
  • 会话、配置和索引写入通过 cell::async_io::file_writer（按路径合并，一个后台线程）。每次写入都是原子替换：内容写入兄弟 <name>.tmp，刷新到存储设备，然后重命名覆盖目标，因此崩溃永远不会留下被下一次启动静默读为空的截断文件。读取这些文件的命令（/save、/sessions、/session、/compact、退出）会先调用 flush() 作为持久性屏障；信号处理器和 RAII 退出守卫也这样做。

运行时数据布局

.cell 锚定到包含 cell 可执行文件的目录（GetModuleFileNameW / /proc/self/exe），而不是当前工作目录——因此无论从哪里启动，bin/cell.exe 都使用 bin/.cell/。

使用记录累计 requests、messages、input_chars、output_chars、input_tokens、output_tokens、total_tokens。[llm] 日志行中显示的提示缓存命中率由 usage.prompt_tokens_details.cached_tokens / prompt_tokens（OpenAI）或 cache_read_input_tokens / (cache_read_input_tokens + input_tokens)（Anthropic）计算。

架构

一切都在 cell.cpp 中，按命名空间拆分，依赖方向严格：只有 cell::plat 了解 OS API，只有 cell::net 了解 curl，只有 cell::encrypt 了解 libsodium。

代理循环

没有固定轮次上限：循环持续到模型在无工具调用的情况下回答、调用被阻止/拒绝、用户取消或发生错误。每一轮记录 round=、上下文大小、token 数、缓存命中率、总时间和首 token 时间。每次用户轮次后，会话和配置都会持久化。

失败与重试。 失败的 LLM 请求每轮最多重试 5 次，尝试之间延迟 5 秒（[retrying in 5s... attempt N/5]）；耗尽后以 [llm error after 5 attempts] 结束该轮，并记录一个中断轮次（参见中断）。如果失败是上下文溢出错误，该轮会压缩一次并立即重试，而不是消耗一次重试尝试（参见自动压缩）。

流式 UI 与键盘控制

  • > 提示符，流式答案前缀 reply>；推理流以暗色打印，答案普通，工具结果及其回显青色。
  • 等待第一个 token 时，每 500 ms 刷新一个 ⏳ Ns 旋转指示器；之后在行边界刷新 ~N tok 计数器。
  • 流式期间按 Esc 取消：该轮被记录为中断——部分回复（思维链和答案文本到目前位置）保留在对话记录中，并打印 [cancelled]。参见中断。（由 cell::plat::peek_key 实现，它会临时将 stdin 置于 raw 模式。）
  • Ctrl+C（以及 Windows 上的 SIGTERM/SIGHUP/SIGABRT）运行持久化钩子——修复工具对话记录、保存会话、保存配置、刷新异步写入——恢复终端并以信号编号退出。终止信号取自专用 sigwait 线程，因此持久化代码永远不会在异步信号处理器内运行。SIGSEGV/SIGFPE/SIGILL 故意不尝试序列化状态：它们恢复默认动作并终止。
  • 非交互模式（stdin 不是 tty）将整个 stdin 作为一条消息读取，要求已配置提供方，运行代理循环一次并退出。

中断与 /reload

一个轮次可以在模型完成之前以两种方式结束：流式期间按 Esc，或 LLM 请求在最后一次重试时失败。无论哪种方式，该轮都不会被丢弃：

  • 模型已经产生的任何内容都会原样保留，并截断到完整到达的最后一个 token（sse_feed 只应用完整流事件，因此累积文本总是结束在 token 边界——不会补全或填充）。
  • 仍在发出的工具调用会被取消：其参数通常是截断的 JSON，从未被批准或执行，也不会为其发明结果。部分助手消息存储时不含其 tool_calls，因此对话记录对每种提供方都保持有效。
  • 会追加一条系统消息记录原因（Esc，或错误及尝试次数）——它是对话的一部分，而不仅仅是控制台输出，因此模型能看到上一轮为何停止。
  • 会话将其记为中断状态（会话文件夹中的 interrupt.json，因此重启后仍存在）。它会被下一条用户消息（包括 /ins）或达到自然结束的 /reload 清除；/clear 也会丢弃它。

/reload 正好从轮次停止处继续：它按现状发送对话记录（部分回复 + 中断通知，无新用户消息），让模型接续。如果该尝试也被中断，状态只会用新原因刷新。/reload 若没有可恢复内容，会报告错误而不是发送任何内容。

日志、信号与退出码

日志行是 [YYYY-MM-DD HH:MM:SS] LEVEL [cat ] message（UTC）。类别包括 boot、core、llm、tool、sess、ctx、cmd、user、probe、provider、model、think、sandbox、skill、stats、vault。只有 llm 和 tool 活动镜像到控制台（ERROR 总是；DEBUG 仅在 --verbose 时），因此终端保持可读，而文件保留一切。写入以 16 KiB 块缓冲，ERROR 立即刷新。

情况退出码
正常退出，或 --selftest 通过0
未知选项 / 缺少选项值1
非交互运行且未配置提供方1
致命 cell::sys::exception 或未处理 std::exception（记录后 RAII 守卫持久化状态）1
被捕获信号终止信号编号

set_terminate 处理器记录任何逃逸异常的类型，set_new_handler 在 abort 前记录内存不足。

自测

在一次性 .cell-selftest/ 根目录上运行（之后删除），覆盖：三种模式下的高风险和沙箱决策，路径/遍历/符号链接/凭据阻止，注入清理器（大小写、\r、零宽、全角、西里尔/希腊、重音、跨行拆分、标点连接、释义、超大输出），wrap_tool_output 防伪造，读/写/write_new/edit（全部五种模式、歧义、部分读取覆盖、no-op），rg/find/ls 语义和守卫，exec 超时和退出码，带引号数字参数，工具注册表及其策略，16 路并发只读工具调用，Teamwork 任务规范化（每子代理 provider/model/think、复用引用、名称清理、限制）、存储往返、子代理追加/移除、历史和报告查询，增量 SSE 解析和缓冲区压缩，惰性目录遍历器，线程池任务记账，日志器轮转，保险库往返和持久化，配置保存/加载/迁移/错误处理，会话分组，/new 语义，cwd 索引，exec 结果加载时重新清理，中断轮次（部分回复截断、工具调用取消、原因通知，以及持久化/清除的中断状态），技能发现（包括目录式）和使用统计。打印 selftest OK / selftest FAILED。

实现说明

一些代码与其自身帮助文本/注释不一致，或行为故意比看起来更简单的地方：

  • 沙箱仅针对路径：box::check_exec / box::check 不解析命令名、解码编码载荷，也不按二进制名阻止网络出口——它们只拒绝路径遍历和敏感路径。网络出口被“拒绝”的意义在于没有允许命令的白名单；exec 改为由沙箱模式、人工确认（或 autoallow）以及高风险二次确认列表门控。
  • 切换提供方会重置模型名：--provider NAME（已有提供方）、/provide NAME 和 /provide add 都通过 config::select_provider，当选择实际变化时清除 current_model。重新选择已激活提供方会保留其模型，空的 current_provider 在该目的下算作“第一个提供方激活”。同一命令行请求的模型（--model）在切换后应用。
  • 启动恢复当前 cwd 中最后使用的会话，记录在 active_sessions；如果尚无记录，则选择该 cwd 最近写入的会话文件。最后五条用户/助手文本消息会再次打印，排除思考和工具调用内容。--session / session 字段仍为兼容性持久化，但启动使用 active-session 记录。
  • exec 是唯一其输出会扫描注入指纹的工具；其他工具在调用时被认为已沙箱化，只获得大小上限。工具描述本身也可能与实现漂移（例如 exec 的拒绝网络声明、read 的带行号），这对于嵌入代码旁边的字符串来说是正常的。
  • 工具输出包装标签在源码中用转义的正斜杠写入；转义在运行时折叠为普通斜杠，因此到达对话记录的标记是一个携带 tool 和 path 属性的开始标签，而重新加载时的清理器根据该属性的 exec 值进行键控。
